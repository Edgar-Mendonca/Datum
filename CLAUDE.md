# DATUM (family hub): notes for Claude

Read `MEMORY.md` first. It is the family memory: decisions for every app, the apps list, the site, and a log of every session.
At the end of every session that changes anything, update `MEMORY.md` (session log, decisions, next steps).

What this repo is:
- The family "brain": `FAMILY.md` (the design guide, source of truth for every app), `MEMORY.md`, `apps.json`, `brand/`.
- The brain: `brain/graph.json`, generated by `node brain/brain.mjs` from FAMILY, MEMORY, apps.json and each app's MEMORY/CHANGELOG/site.json (schema in `brain/BRAIN.md`). Regenerate and commit it at the end of every session.
- The website in `site/` (Astro, static, GitHub Pages at https://edgar-mendonca.github.io/Datum/): one landing page (`index.astro`) and the interactive network (`network.astro` + `src/scripts/network.ts`), deployed by `.github/workflows/pages.yml`. Pages › Source must be GitHub Actions.
- The app repos (`Edgar-Mendonca/Datum-Plan`, `Datum-Plot`, `Datum-Atlas`) are read-only from here. Changes to an app happen in that app's own chat; give the user text to paste there.

Rules:
- Public text never names or compares with commercial products, and never says an app copies or replaces one (FAMILY §13).
- The site's look: simple, professional and technical, for engineers and scientists, never "artistic". Paper-and-ink grid (framed column, numbered section bars), IBM Plex Sans and Mono only (no display or serif faces, no giant words, no floating decorations), FAMILY §3 accents. The hero is two panels: the name and a changing write-up on the left, the animated instrument panel (one technical scene per app, in step with the text) on the right. No "free · open source · Windows" slogans; say it once in the lead. No UI kit. Client JavaScript only for the theme toggle and the network page.
- The brand: the user's "Continuum" logo, `brand/BRAND.md`. Never recolour it in app accents; regenerate the files with `python3 brand/source/build-logo.py brand`.
- The landing page stays one page: what Datum is, the apps with their download buttons, the latest releases. Memory, roadmaps and decisions live in the repo and the network, not as pages.
- Never fail the build because of one app: show "Coming soon" instead.

Checks before pushing:
- `cd site && npm ci && npm run build` (works without a token).
- Playwright screenshots at 1280 and 375 px (`npm run preview`, then check every page for horizontal overflow).
