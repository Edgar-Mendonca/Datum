# DATUM (family hub): notes for Claude

Read `MEMORY.md` first. It is the family memory: decisions for every app, the apps list, the site, and a log of every session.
At the end of every session that changes anything, update `MEMORY.md` (session log, decisions, next steps).

What this repo is:
- The family "brain": `FAMILY.md` (the design guide, source of truth for every app), `MEMORY.md`, `apps.json`, `brand/`.
- The brain: `brain/graph.json`, generated by `node brain/brain.mjs` from FAMILY, MEMORY, apps.json and each app's MEMORY/CHANGELOG/site.json (schema in `brain/BRAIN.md`). Regenerate and commit it at the end of every session.
- The website in `site/` (Astro, static, GitHub Pages at https://edgar-mendonca.github.io/Datum/): one landing page (`index.astro`), one page per app (`pages/apps/[id].astro`) and the interactive network (`network.astro` + `src/scripts/network.ts`), deployed by `.github/workflows/pages.yml`. Pages › Source must be GitHub Actions.
- **Datum Home** in `home/` (Tauri 2 + SolidJS, like the apps): the desktop app that installs, updates, opens and removes the Datum apps. Rules in `crates/core` (unit-tested, no I/O); registry, processes and installers in `src-tauri/src/sys.rs`. It reads `home.json` (written by the site build) and each app's GitHub releases; checks only when opened; installs only verified installers (`SHA256SUMS.txt`) from the app's own releases; never touches the user's files. Released from this repo with tags `home-vX.Y.Z` (`.github/workflows/home-release.yml`); checked by `home-ci.yml`. The site offers both Datum Home and each app on its own.
- The app repos (`Edgar-Mendonca/Datum-Plan`, `Datum-Plot`, `Datum-Atlas`, `Datum-Sim`) are read-only from here. Changes to an app happen in that app's own chat; give the user text to paste there.

Rules:
- Public text never names or compares with commercial products, and never says an app copies or replaces one (FAMILY §13).
- The site's look: simple, professional and technical, for engineers and scientists, never "artistic". Paper-and-ink grid (framed column, numbered section bars), IBM Plex Sans and Mono, plus Instrument Serif italic only for the changing blue words ("Tools to *plan projects.*", "for every *project.*"; class `.it`); no giant words, no floating decorations, FAMILY §3 accents. Glass section bars (sticky, blurred), an index by the ruler with a scroll marker, words coming into focus and cards rising on scroll (CSS scroll timelines). The hero is two panels: "Datum" and "Tools to <phrase>" with the lead and two buttons on the left; on the right four tiles in a square, one per app (`Hero.astro`), each an animated vector drawing of what the app does (`AppGlyph.astro`: Gantt, curve fit, property chart, control loop), around the amber datum square where they meet. The italic phrase changes by itself every few seconds and its app's tile lights up; hover or focus holds a tile, and the cycle resumes when the pointer leaves. Tiles open the app's page. Never more than the current apps; never a count. Never slow, full-panel crossfades. No "free · open source · Windows" slogans; say it once in the lead. No UI kit. Client JavaScript only for the theme toggle, the hero tiles, the index rail and the network page.
- The brand: the user's "Continuum" logo, `brand/BRAND.md`. Never recolour it in app accents; regenerate the files with `python3 brand/source/build-logo.py brand`.
- The landing page stays one page: the hero, 01 the apps (the Datum Home band, then compact cards with a status badge: Stable/Beta/Alpha from apps.json `status` or the version), 02 the method, 03 the newest release of each app. Never say how many apps there are. Each app also has its own page (`/apps/<id>`): hero with the app's drawing and download, 01 Overview (`about` + three `steps`), What it does (highlights), Screens (up to four), Roadmap, Releases (last five, expandable), Get it, previous/next app. Family memory and decisions live in the repo and the network, not as pages. On app pages the italic `.it` takes the app's accent.
- Never fail the build because of one app: show "Coming soon" instead.

Checks before pushing:
- `cd site && npm ci && npm run build` (works without a token).
- For `home/`: `npm ci && npm run check:ui && npm run build:ui`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` (the Windows code: `cargo clippy -p datum-home --target x86_64-pc-windows-gnu`).
- Playwright screenshots at 1280 and 375 px (`npm run preview`, then check every page for horizontal overflow).
